# 为什么策略一个接一个“失效”：共同的病根和一次性的解法（2026-10-04）

一个策略 = **信号**（我们比市场先知道什么）× **执行**（什么时候、以什么身份、在什么市场、用什么价格成交）。过去几周一直在换信号，但这些失败的共同点都在执行这一侧。信号本身多数是真的：

| 信号 | 毛利确实存在的证据 |
|---|---|
| 币安急动后 Polymarket 报价过期（G/H/F） | GitHub 盘口：触发后 110 ms 看到、0.45 秒成交的单每份仍有 +9～12¢ |
| 急动后的延续（动量，gamma 区间） | 币安 31.8 万次急动，DVOL − 已实现波动越高延续越强，两段一致 |
| 收盘前强势方被低估 | 链上挂单方 0.6–0.8、剩 30–60 秒：每份 +5～7¢（9 月后半月，样本外） |
| 晚 1–2 秒进场 | kacho 盘口：晚 1 秒 +5.6¢、晚 2 秒 +3.1¢ |

## 五个共同的病根

1. **战场是专门防我们的。** 5 分钟、15 分钟、1 小时涨跌市场有 150 ms 吃单冻结，冻结期间做市商可以撤单。凡是“看到币安再去吃单”的策略，在这里天然比做市商慢一个冻结期。盘口上最快的吃单在跳变后 +250 ms 才成交，正好等于“币安到欧洲约 100 ms + 冻结 150 ms”；做市商中位 178 ms 就开始改价。
2. **我们还比“必须的慢”多慢了约 120 ms。** 真单试点：被撤单回执 310 ms、成交 375 ms；同在都柏林的实践者只比冻结多 33 / 116 ms。差距稳定在 110–130 ms，大概率在我们的客户端和账户（连接放凉、HTTP/2 被断流、SDK 多余的查询和成交轮询、存款钱包验签），是可以修的。
3. **执行规则把能拿的钱扔掉了，回测还把坑算了进去。** “撮合时边际 ≥ 12¢ 才成交”在 0.45 秒只成交 25%，每张发出的单 +1.0¢（约 $9/天）；同一信号改成“触发时决定、限价放宽到 公平价 − 2～6¢”，每张 +3.9～4.5¢，约 $75–110/天（样本内，检验 J 在验证）。而“触发时不便宜、撮合时才变便宜”的单每份 −15～−28¢，实盘根本不会发，但曲线和检验 G/I 都把它们算了进去。
4. **薄信号付不起吃单的成本。** 动量、晚进场、强势方低估这些信号毛利只有 0.5～2¢，吃单要付 1.75¢ 手续费加半个价差（随机买入的基线是 −1.9¢）。单独吃单永远亏；同样的信号如果用来决定挂单（不付手续费，还有返佣），就能活。多因子叠加正确的方式也在这里：把几个弱信号合成一个报价，只付一次成本（挂单时是零），而不是每个信号各吃一次单。
5. **数据和回测口径制造了“时好时坏”。** 都柏林录制机晚约 50–100 ms、香港晚 0.25–0.5 秒，回测按这些数据算偏乐观；前向检验一跑，看起来就像策略失效了。

## 一次性的解法：改执行，所有信号一起受益

| 杠杆 | 做什么 | 受益的策略 |
|---|---|---|
| A. 我方延迟（必须做） | 客户端整改清单见 LATENCY.md：热 HTTP/1.1 长连接、不走 SDK、预签名；零风险挂单测量；申请伦敦机房托管；币安 SBE `bestBidAsk` 与成交谁先到用谁 | 所有吃单策略；挂单的撤单速度 |
| B. 执行规则 | 触发时决定、限价放宽、不追“后来才出现”的边际（检验 J，10/4 09:00 起） | G、H、F、反向 2 倍、每次都加 |
| C. 换战场 | 没有冻结、按币安 1 分钟 K 线结算的日内市场：“BTC 高于 X”阶梯、价格区间、“会触及多少”、按日和 4 小时涨跌（`ladder.py` 开始录制）。“触及”市场在币安成交到触及价那一刻结果已定，卖一若还低于 0.99 就是纯速度套利 | 所有币安驱动的信号直接搬过去；没有冻结时我们约 120–150 ms |
| D. 换身份 | 在有冻结的市场做挂单方，用信号决定挂哪边、什么时候撤（冻结此时保护的是我们） | 动量、延续、强势方低估、区间因子；外部有人做到 +2.3¢/份，但之后 725 个市场持平、放大就亏，还没证实 |

前四个病根里，A、B、C 各解决一个，D 把第 4 个变成多因子叠加的地方。每一步都先写死规则、只用新录的数据判定。
