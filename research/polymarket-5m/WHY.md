# 为什么策略一个接一个“失效”：共同的病根和一次性的解法（2026-10-04）

一个策略 = **信号**（我们比市场先知道什么）× **执行**（什么时候、以什么身份、在什么市场、用什么价格成交）。过去几周一直在换信号，但这些失败的共同点都在执行这一侧。信号本身多数是真的：

| 信号 | 毛利确实存在的证据 |
|---|---|
| 币安急动后 Polymarket 报价过期（G/H/F） | GitHub 盘口显示部分旧卖一确会留下；但真实 H 只有 10 发 1 成，必须把可成交性与方向收益分开检验 |
| 急动后的延续（动量，gamma 区间） | 币安 31.8 万次急动，DVOL − 已实现波动越高延续越强，两段一致 |
| 收盘前强势方被低估 | 链上挂单方 0.6–0.8、剩 30–60 秒：每份 +5～7¢（9 月后半月，样本外） |
| ~~晚 1–2 秒进场~~（已否定） | kacho 盘口“晚 1 秒 +5.6¢”是每秒快照的假象：同一份 GitHub 毫秒盘口按 kacho 的读法得 +4.0¢，其中 69% 的行还是急动前的旧卖一（这部分 +5.9¢，其余 −0.3¢）；真实发单（0.11–10 秒后发、375 ms 撮合）每份 −0.3～−0.9¢（[`real/late-ms.md`](real/late-ms.md)）。钱只在过期报价里，要靠速度 |

## 五个共同的病根

1. **当前 BTC 5m 战场专门防这种套利。** 它的 CLOB 市场记录为 `itode: true`，当前 changelog 规定 150 ms 吃单冻结；冻结期间做市商可以撤单。其他周期或阶梯不能靠名称推断，必须逐市场查同一字段。凡是“看到币安再去吃 5m 旧单”的策略，天然比做市商慢一个冻结期。
2. **本地热路径已经压完，瓶颈不在签名。** 3 张 timestamped-first 真单的本机收包→发单是 0.776–0.908 ms；交易所时间→发单仍是 112.7–137.2 ms，来自上游发布与跨区传输。发送→回执是 216.9–296.6 ms；此前唯一成交的发送→撮合是 374.9 ms，完整信号→撮合 481.75 ms。不能再把约 120 ms 归因于本地 SDK，也不能用回执时间冒充撮合时间。
3. **执行规则值得改，但旧收益表只是容量上限。** 探索样本中，触发时决定并放宽限价的每发送 EV 高于“撮合时仍便宜 12¢”；但旧的 $75–110/日假定独占记录到的 L1 数量、没有竞争，而且不要求顶层完整满足真实订单，不能当预期收益。修正后的检验 J 使用冻结限价、实盘 5 份/$1 网格、0.50 秒主延迟，并要求届时顶层深度足够；只用 10/4 10:00 UTC 后的新市场。
4. **薄信号付不起吃单的成本。** 动量、晚进场、强势方低估这些信号毛利只有 0.5～2¢，吃单要付 1.75¢ 手续费加半个价差（随机买入的基线是 −1.9¢）。单独吃单永远亏；同样的信号如果用来决定挂单（不付手续费，还有返佣），就能活。多因子叠加正确的方式也在这里：把几个弱信号合成一个报价，只付一次成本（挂单时是零），而不是每个信号各吃一次单。
5. **数据和回测口径制造了“时好时坏”。** 都柏林录制机晚约 50–100 ms、香港晚 0.25–0.5 秒，回测按这些数据算偏乐观；前向检验一跑，看起来就像策略失效了。另外两份历史数据对秒级规则同样偏乐观：kacho.io 每秒一行的快照（`real/late-ms.md`、`real/rt-ms.md`），以及 Hugging Face 的 5–8 月 100 ms 档案（盘口流相对币安流有滞后：同一个 H 在那里 0.5 秒每份 +11.7¢，GitHub 毫秒盘口上只有 +3～5¢；“币安 1 秒 ≥ 4 / 3 秒 ≥ 8 个基点就买、持有到结算”在那里严格卫生下 +3.5¢ / +6.3¢，到 10 月毫秒盘口上是 −10.2¢ / −18.0¢，`real/rt-fwd.md`；MIX 的三条冻结规则在 5–8 月档案上 C 段每份 +4.8～+8.6¢，但单信号对照“急动 ≥ 5.83σ、持有到结算”就有 +7.6¢，同一个对照在 10 月毫秒盘口上 0.11 秒发单只有 +0.87¢ ±1.21、0.3 秒起约 0，≥ 4σ 为 −0.5～−1.4¢，`real/late-ms-z6.md`、`real/late-ms-z4.md`）。秒级的规则只认 GitHub 毫秒盘口和真单。

## 一次性的解法：改执行，所有信号一起受益

| 杠杆 | 做什么 | 受益的策略 |
|---|---|---|
| A. 我方延迟 | 本地收包→发送已低于 1 ms；保留热连接和延迟闸门。免费 SBE 只作为另一条行情竞速通道实测，不预设能省多少；不再做本地微秒级重写 | 防止回退，主要砍尾延迟 |
| B. 执行规则 | 触发时冻结限价和仓位，只在真实盘口仍有足量深度时计成交（修正版检验 J，10/4 10:00 UTC 起） | G、H、F、每次都加 |
| C. 换战场 | 逐个调用 CLOB `/clob-markets/{condition_id}`，只录 `itode` 非 true 的候选；优先周/月“会触及多少”和日阶梯。触及盘按 Binance 最终 1 分钟 High/Low 结算；4 小时涨跌是 Chainlink TWAP，不能当 Binance 确定性套利 | 避开 150 ms 冻结，但仍须证明盘口与网络可成交 |
| D. 换身份 | 在有冻结的市场做挂单方，用信号决定挂哪边、什么时候撤（冻结此时保护的是我们） | 动量、延续、强势方低估、区间因子；外部有人做到 +2.3¢/份，但之后 725 个市场持平、放大就亏，还没证实 |

英国在官方地区限制中禁止开仓，且没有找到官方“伦敦托管/KYC 表”文档，所以不把搬伦敦列为方案。`secondsDelay` 是整秒字段，也不能识别 150 ms；当前可靠开关是 CLOB 返回的 `itode`。每一步都先写死规则、只用新录的数据判定。
