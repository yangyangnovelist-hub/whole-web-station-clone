# 50 盘小样本试跑（CronosVirus00 数据）

> 仅作流程验证，**不能**用来判断策略是否赚钱。样本只有 50 个 BTC 5 分钟盘、约 4 小时。

## 数据与处理

- 来源：公开仓库 [CronosVirus00/polymarket-BTC5min-database](https://github.com/CronosVirus00/polymarket-BTC5min-database)（CC BY 4.0，© 2026 CronosVirus00），`market_data/*.parquet`，615 个文件，175,829 行订单簿快照。
- 覆盖：50 个市场，窗口开始 2026-04-16 07:10 至 11:15 UTC。原计划用的 kacho.io HF 数据集在本环境被网络策略拦截（huggingface.co / hf-mirror.com / modelscope.cn 均为 CONNECT 403）。
- 每行是一个 token 的完整盘口（bids 升序、asks 降序），取 max(bid)、min(ask) 为最优价。36 个市场只有一个 token 的盘口，14 个有两个；每个市场取行数多的那个 token 记作“Up”。策略按强势/弱势方定义，对 Up/Down 标签对称，所以这个任意指定不影响策略行；但校准表和“Up 胜率”没有意义。
- 数据里没有结算结果。收盘时盘口是单边的：胜方 token 只剩 bid 0.99（无 ask），败方只剩 ask 0.01（无 bid），据此判定：最后一笔 bid ≥ 0.9 记胜，ask ≤ 0.1 记负。50 个全部可判定（29 胜 / 21 负，相对被选 token）。例外：`btc-updown-5m-1776326700` 数据在收盘前 44 秒结束，当时 mid 0.025，按负处理。这是用盘口推断结果，不是链上结算。
- 最后一笔 tick 相对收盘：中位数晚 1.5 秒，最早提前 44.5 秒（上面那个市场），最晚晚 4.9 秒。

复现：

```
python - <<'PY'
import pandas as pd, numpy as np, glob, json
df = pd.concat([pd.read_parquet(f, columns=['timestamp','slug','asset_id','bids','asks'])
                for f in sorted(glob.glob('market_data/*.parquet'))], ignore_index=True)
best = lambda s, fn: (lambda l: fn(float(x['price']) for x in l) if l else np.nan)(json.loads(s))
df['bid'] = df.bids.map(lambda s: best(s, max)); df['ask'] = df.asks.map(lambda s: best(s, min))
df['end'] = df.slug.str.rsplit('-', n=1).str[1].astype(int) + 300
top = (df.groupby(['slug','asset_id']).size().reset_index(name='n')
         .sort_values('n').drop_duplicates('slug', keep='last'))
a = df.merge(top[['slug','asset_id']], on=['slug','asset_id']).sort_values('timestamp')
last = a.groupby('slug').tail(1).set_index('slug')
won = np.where(last.bid >= 0.9, 1, np.where(last.ask <= 0.1, 0, np.nan))
pd.DataFrame({'condition_id': last.index, 'outcome': won, 'end_ts': last.end.values}).to_parquet('btc_markets.parquet')
pd.DataFrame({'condition_id': a.slug, 'ts': a.timestamp, 'bid_up': a.bid, 'ask_up': a.ask}).to_parquet('btc_ticks.parquet')
PY
python backtest_book.py btc_markets.parquet btc_ticks.parquet --out real/cronos50.md
```

## 解读（先看这里）

- **没有任何一行能说明有优势。** 每行只有 2–24 笔，远低于报告里提示的约 300 笔门槛。
- 扫尾盘（买 0.97–0.99 的强势方）8–9 笔全胜，t 值 +8 到 +11 是**假象**：全胜时样本方差为 0，t 值被撑大。按成本 0.977 的隐含胜率，9 笔全胜的概率本来就有 81%。一次失败亏约 0.98，要约 45 次 +2.2¢ 的赢才能补回。
- 买强势方 0.80–0.97 @30s：18 笔全胜，纯靠运气出现的概率约 18%。同一策略 @120s 却是 −9.5¢、@10s 是 −1.9¢，符号来回翻，是噪声。
- 弱势方 0.03–0.20 @30s 的 t = −7.6，同样是 0 胜导致的零方差。
- 校准表为空，因为每个区间都不到 30 个样本。
- 结论：这份数据只能证明流程能跑通、盘口字段能读，不能用来判断赚不赚钱。要下结论，需要 kacho.io 数据集（约 1.57 万个 BTC 盘）或同等规模的数据，并做前后两半的样本外检验。

## 工具输出

市场数 50（btc），时间 2026-04-16 至 2026-04-16。吃单按当时 ask 成交，taker 费率 0.07，每笔 1 份持有到结算。
快照取收盘前 τ 秒或更早的最后一个 tick（最多早 5 秒）。Down 的 ask 取 1 − Up 的最佳 bid（有 Down 盘口时与之取优）。
